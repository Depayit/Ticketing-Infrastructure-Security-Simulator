กรณีศึกษาและการทดสอบ Red Team vs Blue Team

กรณีศึกษาการทดสอบจำลองเหตุการณ์จริง (Simulation Scenarios) บนคอนเสิร์ต 2026 JACOB WORLD TOUR IN BANGKOK

Scenario A — Basic Burst Bot → IP Layer Block IP Blocked

สคริปต์บอทส่ง Request ถี่สูงเกินกำหนด (>15 req / 5s) ไปยัง GraphQL Endpoint: 

for i in {1..20}; do
  curl -s -o /dev/null -w "%{http_code}\n" \
  -X POST http://localhost:8090/graphql/v2 \
  -H "Content-Type: application/json" \
  -d '{"query":"query { queueStatus(eventId: \"demo-concert-2026\") { status token } }"}'
done
ผลลัพธ์: ถูก Gateway สั่งตัดการทำงานทันทีด้วยรหัส 429 RATE_LIMIT_BURST
Scenario B — Advanced Bot → AI Layer Block AI Fraud Blocked

รัน worker/bot.py ยิงตรงข้ามคิวโดยไม่มี Telemetry เมาส์และสคริปต์เซนเซอร์:

  • _token_warmup_loop แอบขอ Token ล่วงหน้า
  • _purchase_wave_custom ยิง Concurrent addToCart
  • ไม่มี Mouse Movement / Scroll Velocity events
ผลลัพธ์: AI Fraud Engine ตรวจพบความผิดปกติ ส่งรหัสปฏิเสธ 403 FRAUD_DETECTED
Scenario C — Human User → Passed All Layers Success Commit

ผู้ใช้งานจริงเข้าผ่านเบราว์เซอร์ http://localhost:8090/:

  1. รอผ่านห้องรอ Waiting Room (Akamai Sensor คำนวณ Bot Score ต่ำ)
  2. ขยับเมาส์ เลื่อนหน้าจอ และคลิกเลือกที่นั่ง (Telemetry ส่งอัตโนมัติ)
  3. กรอก OTP 123456 ที่หน้าชำระเงิน 3DS
ผลลัพธ์: ทำรายการสำเร็จ ที่นั่งถูก Commit เข้าสู่ฐานข้อมูล

ภาพถ่ายการเข้าซื้อตั๋วของผู้ใช้งานจริงทุกขั้นตอน (End-to-End Human Flow):

1. Entry Zone Modal

2. Countdown Timer

3. Priority Queue

4. เลือกรอบการแสดง

5. ผังเลือกที่นั่ง

6. กรอกชื่อผู้เข้าชม

7. เลือกช่องทางจ่ายเงิน

8. 3DS QR Payment

9. ชำระเงินสำเร็จ

Scenario D — Bot Evasion → 3DS Layer Block 3DS Fail

ทดลองปิดชั้น AI Layer ด้วยการตั้งค่า AI_LAYER_ENABLED=false:

บอทสามารถล็อกที่นั่งได้ชั่วคราว แต่เมื่อถึงขั้นตอนสุดท้าย ไม่สามารถกรอก OTP หรือยืนยันตัวตน 3DS Payment ได้

ผลลัพธ์: 3DS Timeout หรือ OTP ล้มเหลว ส่งผลให้คำสั่งไม่ถูก Commit และสิทธิ์ที่นั่งถูกคืนเข้าพูล (Seat Release)
