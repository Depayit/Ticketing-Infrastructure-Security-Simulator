สถาปัตยกรรมระบบเชิงลึก (Deep Architecture)

โครงสร้างการทำงานของไมโครเซอร์วิส เส้นทางการเดินทางของข้อมูล (Data Flow) และโปรโตคอลการสื่อสาร

ลำดับขั้นตอนการประมวลผลคำสั่งกดซื้อตั๋ว (Request Lifecycle Flow)

1. Queue-it & Priority Admission Engine Redis ZSET

ระบบจัดลำดับคิวห้องรอซื้อตั๋ว (Virtual Waiting Room) ใช้โครงสร้างข้อมูล Redis Sorted Set (ZSET) โดยใช้ค่า Bot Score (0–100) เป็นน้ำหนักหลักในการคำนวณคิว:

  • มนุษย์แท้ (Bot Score < 20): ได้รับ Score ต่ำ ถูกจัดอยู่อันดับต้นของ ZSET และผ่านคิวเข้าเลือกที่นั่งทันที
  • บอทน่าสงสัย (Bot Score 55–75): ได้รับการปรับตำแหน่งคิวถอยหลังแบบสุ่ม (Inflated Queue Position) พร้อมบังคับผ่าน Interactive Challenge Modal
  • บอทร้ายแรง (Bot Score > 75): ถูกปฏิเสธการเข้าคิวอัตโนมัติ (Admission Block)
2. Seat Pessimistic Locking & Fraud Gate Redis Atomic Lock

เพื่อป้องกันปัญหา Overbooking และการยิง API แย่งล็อกที่นั่งของบอทความเร็วสูง:

  • Atomic Locking: ใช้ Redis SET lock:seat_id user_id NX EX 300 เพื่อล็อกที่นั่งเป็นเวลา 5 นาทีแบบ Pessimistic Lock
  • Fraud Gate Validation: ทุกคำขอล็อกที่นั่งต้องผ่านการตรวจสอบ Token Validation และคะแนนความเสี่ยงจาก AI Fraud Engine ก่อนสิทธิ์ล็อกจะถูกบันทึก
  • Auto Release: หากกระบวนการชำระเงินไม่เสร็จสิ้นภายใน 300 วินาที ที่นั่งจะถูกคลายออกเข้าสู่ Pool อัตโนมัติ
