ระบบป้องกันความปลอดภัย (Defensive Security Stack)

TTM Defense Demo — กลไกป้องกันความปลอดภัยแบบ Swiss Cheese Model + Akamai Bot Manager Simulation

แนวคิดโมเดลการป้องกันแบบเน้นความลึก (Swiss Cheese Security Model)

ไม่มีชั้นการป้องกันใดที่สมบูรณ์แบบ 100% (แต่ละชั้นเสมือนมีรูเนยแข็ง) การออกแบบระบบป้องกันตั๋วชั้นนำจึงใช้การซ้อนทับกันหลายชั้น เพื่อให้รูรั่วของชั้นหนึ่งถูกปิดกั้นด้วยอีกชั้นหนึ่ง:

Layer 1: Edge / IP

Network & Edge WAF

ดักจับ Basic Bots, Datacenter IPs, Traffic Bursts และยิง HTTP Request รวดเร็วผิดปกติ (>15 req/5s)

Layer 2: Behavioral AI

Telemetry & Fraud Engine

ดักจับ Headless Bots หรือ API-only ที่ผ่าน IP มาได้ แต่ไม่มีการเคลื่อนที่ของเมาส์/การสกอร์ล (Mouse/Scroll Biometrics)

Layer 3: Payment 3DS

3D-Secure Verification

ดักจับ บอทกดบัตรที่หลุด AI มาได้ แต่ติดขั้นตอน OTP ยืนยันตัวตนธนาคาร ไม่สามารถ Commit การชำระเงินได้

กลไกจำลอง Akamai Bot Manager (`akamai-sensor.js`)

จำลองระบบ Bot Detection ระดับโลกของ Akamai ผ่านสคริปต์เซนเซอร์และการประเมินคะแนนความเสี่ยง:

Component Details & Value Ranges Behavioral Impact
Bot Score 0 – 100 (0 = มนุษย์แท้, 100 = บอทชัดเจน) ส่งผลโดยตรงต่อตำแหน่งคิว Queue-it และการตัดสินใจส่ง Challenge Modal
Session Cookies _abck, ak_bmsc (HttpOnly), bm_sv บันทึกสถานะการยืนยันตัวตนและการนับจำนวน Request ต่อเซสชัน
Sensor Payload akamai-sensor.js → POST /api/sensor เก็บสัญญาณพฤติกรรม >100 สัญญาณ ถอดรหัสลับด้วย PRNG Shuffle
Bot Challenge เมื่อ Bot Score ≥ 55 → _abck status -1 แสดงหน้าต่าง Interactive Challenge ปลดล็อกเมื่อกดยืนยันสำเร็จ (/api/challenge/pass)

ภาพถ่ายระบบจริงในส่วน Akamai Bot Manager & Queue

Akamai Bot Score: 21 / 100

หน้าคิวแสดงผล Priority: สูง (มนุษย์) สำหรับผู้ที่ผ่านการยืนยัน Sensor สกอร์ต่ำ

Akamai Drag Puzzle Challenge

หน้าต่างเรียงลำดับเนื้อเพลงเพื่อยืนยันตัวตนเมื่อ Bot Score สูง (≥55)

Challenge Error Alert

แจ้งเตือน "เรียงภาพผิด กรุณาต่อคิวใหม่" หากตอบ Drag Puzzle ผิดพลาด

Seat Map Selection

ผังเลือกโซนที่นั่ง VIP/Red/Blue พร้อม Pessimistic Seat Locking

Defense Admin Dashboard

หน้าแอดมินสตรีมบันทึกการบล็อกสดทุก Layer และควบคุมสวิตช์ Edge/WAF, Sensor, GraphQL

Defense Layer 1 (IP Check)

หน้าสมาชิกล็อกอินก่อนเวลาเปิดขายพร้อมการตรวจ IP At Gateway

มาตรการล็อกดาวน์การข้ามคิว (GraphQL Lockdown Controls)

บอทส่วนใหญ่มักพยายามยิง GraphQL/API โดยตรงเพื่อข้ามหน้าห้องรอ Queue-it ระบบนี้มีสวิตช์ควบคุมมาตรการเข้มงวด:

Environment Variable Default Description & Security Enforcement
GRAPHQL_ENABLED false เมื่อตั้งเป็น false จะทำการปิด /graphql/v2 บล็อกบอทที่พยายามยิง GraphQL ข้ามคิวทันที
BOT_BYPASS_BLOCK true บล็อก API ที่มี Header สัญลักษณ์บอท (เช่น apollographql-client-name) หรือคำขอที่ไม่มีเซสชัน Akamai Sensor
BOT_CHALLENGE_THRESHOLD 55 เกณฑ์คะแนน Bot Score ขั้นต่ำที่ระบบจะเริ่มส่ง Challenge ให้ผู้ใช้แก้เพื่อยืนยันตัวตน
EDGE_DDOS_GLOBAL_RPS 800 จำกัดจำนวน Request รวมทั้งคลัสเตอร์ (Global Cluster Cap) ป้องกันระบบล่มจาก DDoS

กลไกป้องกันชั้นชำระเงิน (3D Secure & Payment Verification Gate)

ด่านสุดท้ายของการป้องกัน: การยืนยันสิทธิ์การชำระเงินผ่าน 3D Secure, การตรวจสอบ Carding และการ Commit รายการสิทธิ์ที่นั่งเข้าสู่ฐานข้อมูล:

1. ลงทะเบียนชื่อผู้เข้าชม

ระบบบังคับระบุชื่อ-นามสกุลผู้เข้าชมตรงตามบัตรประชาชน ป้องกันสแคปเปอร์เปลี่ยนชื่อ

2. เลือกวิธีชำระเงิน

รองรับช่องทางชำระเงินหลากหลาย (บัตรเครดิต/เดบิต, มือถือ, WeChat/Alipay, Shopee, QR)

3. 3D Secure Gateway

หน้าต่างจำลองสแกนชำระเงิน QR Code แบบ 3D Secure OTP Verification

4. ชำระเงินสำเร็จ (Commit)

แจ้งเตือน "การชำระเงินเสร็จสิ้น!" ยืนยันสิทธิ์การถือครองบัตรเข้าสู่ DB
